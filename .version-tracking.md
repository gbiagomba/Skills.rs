**The design change, and why it was required rather than optional**

Each adapter previously declared a hardcoded list of peer agents sharing a root.
Adding Copilot falsified two of those lists at the same time:

1. `codex.rs` declared `shared_with: vec!["gemini"]`. Copilot also reads
   `~/.agents/skills`, so the disclosure would have named one of two readers.
2. `claude.rs` declared the project `.claude/skills` root as having no peers.
   Copilot CLI documents reading project `.claude/skills`, so that root stopped
   being isolated entirely.

Both errors run in the dangerous direction: they *understate* exposure. A
declared list is only correct until the next adapter lands, so sharing is now
computed in `registry::readers_of`. `SkillRoot` keeps only `agent_specific`,
which is a fact an adapter genuinely knows about itself.
`a_claude_project_install_discloses_that_copilot_reads_it_too` pins the case that
no adapter declares.

**Release pipeline bug found and fixed**

The v1.0.0 release published with **zero assets**. Each build job uploaded
`target/release/skill` under an artifact name that encoded the platform, but the
file inside did not, so `actions/download-artifact` with `merge-multiple: true`
collapsed all six platforms into one `skill` file and the release glob `skill-*`
matched nothing. Fixed by renaming each binary to its documented asset name in
the job that builds it (`.github/workflows/ci-release.yml`, "Stage the release
asset" and the three cross-build equivalents), plus a guard in the release job
that fails when no assets are found rather than publishing an empty release.

Also confirmed in this cycle: the Windows test fixes from v1.0.0 work. The
`Build and Test (windows-latest)` job passed in 2m08s where it previously failed.

**Decisions recorded**

- `gh-copilot` is deliberately **not** an alias. It names the `gh copilot`
  extension, deprecated 2025-10-25, which never supported skills; accepting it
  would imply we manage something we do not
- Project `.claude/skills` is discovered for Copilot but **never written**: a
  skill placed there would appear to belong to Claude Code
- `SymlinkSupport::Undocumented` for Copilot. Its changelog says symlinks load
  from 1.0.62, but GitHub documents nothing and has an open issue (#3264) about
  Windows, so `skill link` is not promised there
- Copilot org and enterprise skills have no local file (relay-fetched on demand),
  so they are reported as unmanageable rather than classified as a local install
- `gh skill` writes provenance metadata into `SKILL.md` frontmatter. We already
  preserve unknown keys so it survives, but re-homing breaks `gh skill update`.
  Recorded as a caveat, not handled

**Bugs found and fixed during implementation**

1. **Rollback compared the wrong digest.** It compared the destination against
   the backup's saved content (`digest_before`), which always differs after a
   successful write, so every legitimate rollback would have been refused. Fixed
   by recording `digest_after` on the backup row via
   `Store::record_backup_result`, called only after the write is verified.
   Caught by `rollback_restores_the_previous_contents`.
2. **Re-running `copy` silently discarded local edits.** `install` treated any
   path with a deployment row as ours to overwrite, so re-installing over an
   edited deployment destroyed the edit, violating the product promise. Fixed by
   splitting the guard into two refusals: never-managed gives exit 11, drifted
   gives exit 3. Caught by a manual smoke test, now pinned by
   `reinstalling_over_a_locally_edited_deployment_refuses_rather_than_discarding`.
3. **`sync` exited 0 on a conflict**, giving a script no signal. Now returns 3
   via `ReconPlan::reject_if_conflicted`, while plain drift stays 0 because
   preserving an edit is sync working as designed.
4. **`thiserror` field collision.** Variants using `source: String` for a source
   locator failed to compile, since `thiserror` reserves `source` for the error
   cause. Renamed to `locator`.
5. **A test asserted the wrong precedence.** `no_baseline_requires_an_explicit_decision`
   expected the no-baseline message for an unmanaged destination, but provenance
   correctly takes precedence over drift. The code was right; the test was fixed
   to exercise both paths.

**Decisions recorded**

- **MSRV is 1.88, not the 1.85 planned.** Transitive `icu_*` and `time` require
  1.88. Verified with `cargo +1.88 check --locked --all-targets`
- `zip` resolved to 7.2.0 and `gix` to 0.87.1 because cargo honours the declared
  MSRV; newer majors need a newer toolchain
- `smb2` 0.27 chosen over `pavao`: pure Rust, no `libsmbclient`. It does pull
  tokio (320 crates with the feature on, 285 without), which is documented
- `SKILL_AGENT_HOME` added. Without it there is no way to test end to end without
  writing into the developer's real agent installation. It is namespaced
  deliberately; `$HOME` is still never honoured for agent roots
- Exit code 12 added for "documented but not implemented in this build"
- Missing frontmatter `name` is a warning plus a Gemini-scoped error, not a hard
  error, because Claude Code and Codex both fall back to the directory name
